1.2 Cloud IAM (Rôles, Groupes & Comptes de Service)

Type de Rôle Description Recommandation Examen ACE
Basic / Primitif Viewer, Editor, Owner. Rôles historiques très larges s'appliquant à l'ensemble du projet. À proscrire en prod. Violent le principe du moindre privilège.
Predefined (Prédéfini) Créés et maintenus par Google pour chaque service (ex: roles/storage.objectViewer, roles/compute.instanceAdmin.v1). Meilleure pratique. Granulaires et mis à jour automatiquement par Google.
Custom (Personnalisé) Créés par vos soins avec une liste précise de permissions élémentaires (ex: compute.instances.start). À utiliser uniquement si aucun rôle prédéfini ne répond au besoin. Ne peuvent pas être appliqués sur des dossiers (Folders).
💡
Règle d'or de l'examen — Google Groups for IAM : N'attribuez jamais de rôles directement à des adresses individuelles. Créez un Groupe Google (ex: devs-backend@societe.com), assignez le rôle au groupe, puis ajoutez/retirez les personnes dans ce groupe.

Compute Engine : Bonnes Pratiques

  • Machine Families : E2 (économique, équilibré), N2 (polyvalent de base), C2 (optimisé pour le calcul lourd), M2 (mémoire géante jusqu'à 12 To pour SAP HANA).
  • Snapshots incrémentiels : Stockés de façon multi-régionale dans Cloud Storage par défaut, assurant une tolérance aux pannes maximale.

Managed Instance Groups (MIGs)

  • Instance Template : Le plan de fabrication immuable utilisé pour cloner les VMs.
  • Autohealing : Redémarre ou recrée automatiquement une VM si le Health Check HTTP échoue.
  • Autoscaling : Ajoute des VMs lors de pics de charge CPU ou de trafic réseau.
💰
Spot VMs (anciennement Preemptible) : Instances offrant une réduction de 60% à 91%. Google peut les arrêter à tout moment avec un préavis de 30 secondes. Parfaites pour du calcul batch, du rendu vidéo ou des workers GKE secondaires. Jamais pour des bases de données de prod !

↔️ HPA (Horizontal Pod Autoscaler) : Ajoute ou retire des répliques de Pods selon l'utilisation CPU/RAM.
↕️ VPA (Vertical Pod Autoscaler) : Réajuste dynamiquement les demandes CPU/mémoire d'un Pod existant.
🖥️ Cluster Autoscaler (CA) : Commande l'ajout ou la suppression de VMs Compute Engine quand des Pods sont bloqués en Pending.

GKE Standard vs GKE Autopilot

  • GKE Standard : Vous choisissez le type de VM, la taille des disques et les OS des nœuds. Vous payez pour les VMs, qu'elles soient pleines ou vides.
  • GKE Autopilot (Recommandé) : Google gère entièrement l'infrastructure des nœuds, le durcissement de sécurité et l'OS. Vous ne payez que pour les ressources CPU et mémoire réellement demandées par vos Pods.

App Engine : Standard vs Flexible

  • Standard : Déploiement de code pur dans un bac à sable (sandbox). Démarrage en millisecondes, scale to zero complet en période creuse.
  • Flexible : Exécute des conteneurs Docker personnalisés sur des VMs Compute Engine. Permet l'accès SSH et les bibliothèques système natives, mais ne scale pas à zéro (1 VM minimum facturée en continu).

Stockage Objet (Cloud Storage) & Analytics

Stockage & Big Data

4.1 Cloud Storage (GCS) : Classes & Cycle de Vie

Classe de Stockage Engagement Minimum Fréquence d'Accès Cas d'Usage Examen
Standard Aucun Fréquente (quotidienne) Données actives, sites web, assets média consultés régulièrement.
Nearline 30 jours < 1 fois par mois Sauvegardes mensuelles de données, rapports périodiques.
Coldline 90 jours < 1 fois par an Plans de reprise d'activité (DR), archives annuelles rarement lues.
Archive 365 jours Quasiment jamais Conformité légale et financière (5 à 10 ans) au coût le plus bas.
⏳
Règles de Cycle de Vie (Lifecycle Management) : Définissez des règles automatisées : par exemple, basculer les fichiers vers Nearline après 30 jours, puis Archive après 90 jours, et supprimer définitivement après 365 jours.

4.2 BigQuery, Dataflow & Pub/Sub

Pub/Sub

Bus de messagerie asynchrone mondial entièrement managé. Découple les producteurs et consommateurs avec abonnements en mode Pull ou Push.

Dataflow

Moteur de traitement unifié pour le streaming (temps réel) et le batch, basé sur Apache Beam. Autoscaling automatique des workers.

BigQuery

Data Warehouse serverless petabyte-scale avec requêtes SQL standard. Optimisation des coûts via le Partitionnement (par date) et le Clustering.

Réseau, VPC, Load Balancing & Sécurité

Réseau & Périmètre

6.1 Architecture VPC Mondial & Shared VPC

🌐
Le VPC Google Cloud est MONDIAL (Global) : Contrairement à d'autres fournisseurs où le VPC est enfermé dans une région, un VPC Google Cloud englobe la planète entière. Ce sont les sous-réseaux (Subnets) qui sont régionaux. Deux VMs situées dans des régions différentes sur le même VPC communiquent directement par leur IP privée via la dorsale de fibre optique privée de Google sans jamais traverser l'Internet public !

Shared VPC (VPC Partagé)

Permet à une organisation de connecter plusieurs projets au même réseau d'entreprise. Géré par un Host Project (administré par l'équipe réseau) et consommé par des Service Projects (utilisés par les équipes de développement).

VPC Network Peering

Connecte deux VPCs distincts de façon privée sans passerelle VPN. Important pour l'examen : le Peering n'est pas transitif (si le VPC A est lié au VPC B et le VPC B au VPC C, A ne peut pas communiquer directement avec C).

6.2 Cloud Firewall & Cloud IAP

  • Pare-feu avec état (Stateful) : Si une connexion entrante est acceptée, la réponse sortante est automatiquement autorisée sans règle supplémentaire.
  • Priorités des règles : De 0 (priorité la plus haute) à 65535 (règle par défaut la plus basse).
  • Ciblage recommandé : Appliquez vos règles via des Network Tags ou mieux, via des Service Accounts rattachés aux instances.
  • Cloud IAP (Identity-Aware Proxy) : Permet d'administrer vos VMs en SSH/RDP sans adresse IP publique et sans passerelle VPN via un tunnel chiffré sécurisé par IAM.

6.3 Cloud Load Balancing (Équilibrage de Charge)

Type de Load Balancer Portée Couche OSI Fonctionnalités Clés
External Application LB (HTTP/S) Mondiale (Global) Layer 7 (HTTP/HTTPS) Une seule IP Anycast mondiale. Terminaison SSL, routage par URL/path, intégration Cloud CDN et Cloud Armor (WAF/DDoS).
External Network LB Régionale Layer 4 (TCP/UDP) Pass-through transparent ultra-rapide sans proxy. L'adresse IP source du client est intégralement préservée.
Internal Application / Network LB Régionale Layer 7 ou Layer 4 Équilibrage privé interne pour les architectures microservices et les communications inter-VMs.

CI/CD & Monitoring

7.1 CI/CD & Déploiement

Cloud Build

Moteur CI/CD serverless. Exécute des builds déclarés dans un fichier cloudbuild.yaml ou un Dockerfile. Déclencheurs automatiques sur commits GitHub/GitLab.

Artifact Registry

Successeur moderne de Container Registry. Stocke vos conteneurs Docker OCI et packages (npm, Maven, Python) avec scan automatique des vulnérabilités.

Terraform / Deployment Mgr

Infrastructure as Code (IaC) pour provisionner et maintenir de manière déclarative l'ensemble de vos ressources cloud.

Fiche Réflexe Anti-Pièges Examen ACE

Spécial Examen
Si la question mentionne... La bonne réponse doit contenir... Le piège à éviter
"Empêcher la suppression accidentelle d'un projet de production même par un Owner" Project Lien (resourcemanager.projects.delete) Ne pas proposer de retirer le rôle Owner (le Lien protège même contre les Owners).
"Attribuer des accès à une équipe de 15 développeurs" Créer un Groupe Google et lui assigner un rôle Predefined Ne jamais assigner de rôles directement aux adresses individuelles.
"Application conteneurisée sans état avec variation imprévisible de trafic de 0 à 10 000 req/s" Cloud Run (scale to zero et scale instantané) Ne pas choisir Compute Engine ou GKE qui nécessitent de payer pour des machines allumées en continu.
"Base de données relationnelle SQL avec SLA de 99.999% et expansion mondiale" Cloud Spanner Cloud SQL ne scale pas horizontalement et est limité à une région.
"Accès SSH à une VM Compute Engine sans IP publique et sans VPN" Cloud IAP (Identity-Aware Proxy) Ne pas créer de serveur Bastion exposé avec une IP publique.
"Sauvegarder des logs pour conformité légale pendant 7 ans au coût le plus bas" Log Sink vers Cloud Storage (classe Coldline ou Archive) Ne pas conserver les logs dans Cloud Logging ou BigQuery qui coûtent beaucoup plus cher.
"Calcul batch ou rendu 3D tolérant aux pannes avec réduction maximale des coûts" Spot (Preemptible) VMs Ne pas utiliser des instances réservées ou standard à plein tarif.
"Permettre à un client externe de télécharger un fichier GCS sans compte Google" Signed URL (URL signée avec durée d'expiration) Ne jamais rendre le bucket public en lecture à tout le monde.
